# TvTracker — notes for Claude

Letterboxd-style TV tracker: watch log, 0–100 % ratings, reviews, lists, follows with private
accounts. TV metadata from TMDB, cached in SQLite. See `README.md` for setup and features.

## Stack & versions

- Next.js 16 App Router (`src/app`), React 19, TypeScript strict, Tailwind CSS 4 (`@theme` +
  `@utility` primitives in `src/app/globals.css`: `card`, `input`, `btn-primary`, `btn-secondary`, `navlink`, `label`).
- Prisma 7 with the `prisma-client` generator → output `src/generated/prisma` (gitignored; run
  `npx prisma generate`). SQLite via `@prisma/adapter-better-sqlite3`; the client singleton is
  `src/lib/db.ts`. Config lives in `prisma.config.ts` (URL comes from `.env` via dotenv), not in the schema.
- Node ≥ 22 (dev machine: 24). `better-sqlite3` and Prisma have install scripts; npm may need
  `npm approve-scripts better-sqlite3 prisma @prisma/engines`.
- Next 16 specifics: `params`/`searchParams` are Promises; `cookies()` is async; use the global
  `PageProps<'/route'>` / `LayoutProps<'/route'>` helpers (generated by `next typegen`, which
  `npm run typecheck` runs first — a fresh route shows `AppRoutes` errors until then). Middleware is `proxy.ts` (not used).

## Commands

- `npm run dev` – dev server. `npm run check` = lint + typecheck + Vitest. `npm run build` for prod.
- Schema change → edit `prisma/schema.prisma` → `npm run db:migrate -- --name <what>`.
- Unit tests live in `tests/` and only cover pure modules (`ratings`, `policies`, `dates`); anything importing `server-only` can't be unit-tested there.

## Conventions (keep these true)

1. **`ensure*` before any FK.** Every server action that attaches user data to TMDB items goes
   through `resolveTarget()` so the Show/Season/Episode rows exist first. Pages call
   `ensureShow/ensureSeason/ensureEpisode` and `notFound()` on null.
2. **`policies.ts` is the single source of visibility truth.** Pages *and* actions use it; never
   inline an `isPrivate` check. Profile tabs call `loadProfile()` and return `null` when
   `!canView` (the layout renders the private notice). Reviews on item pages are filtered with
   `visibleAuthorFilter`. Ratings from private users still count in averages.
3. **`recordActivity` on every user-visible mutation** (LOG, RATING, REVIEW, LIST_CREATED).
   Re-rating / editing a review replaces the previous feed row for that rating/review.
   Logging a whole season writes ONE activity row with `seasonId` and no `logEntryId`.
4. **Ratings are integers 0–100.** Display via `scoreFrom`: users' mean when ≥1 rating, else
   TMDB `vote_average × 10` labelled "TMDB" (`ScoreBadge`). A rating on a log entry is a
   snapshot on `LogEntry.rating` AND upserts the standing `Rating`.
5. **Log ordering.** `LogEntry.watchedAt` = chosen date + current clock time
   (`combineDateWithNow`); season logs add 1 s per episode. Sort `watchedAt desc, createdAt desc`;
   show the date only. "Watched" = `WatchedMark` OR any `LogEntry`.
6. **Polymorphic targets** (`Rating`, `Review`, `ListItem`, `Activity`) set exactly one of
   `episodeId` / `seasonId`; SQLite's NULL-distinct unique indexes make the per-user uniques work.
7. **Never export non-action helpers from a `'use server'` file** — every export becomes a
   public POST endpoint. Shared helpers go in `src/lib`.
8. **`Follow.status` and `Activity.type` are strings**; allowed values are in `src/lib/constants.ts`.
9. After mutations, actions call `revalidatePath("/", "layout")` (simple, whole-app refresh).
10. Server components can be async and query Prisma directly; client components (`'use client'`)
    call actions via `<form action>` / `useActionState`. `SubmitButton` gives pending state.

## Gotchas

- `.env` is gitignored and user-owned (TMDB key + `DATABASE_URL`). `.env.example` documents it.
- Editing a page while a dialog is open resets client state (HMR) — expected in dev.
- Prisma's `prisma init` dropped agent-skill folders (`.claude/skills`, `.agents`, `.windsurf`, `skills-lock.json`); they are optional reference material, safe to delete.
